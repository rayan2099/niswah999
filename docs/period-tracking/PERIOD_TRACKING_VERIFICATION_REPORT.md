## What VERIFIED means here

A case is VERIFIED only when a named, automated test asserts its expected
behavior and that test passes on this branch. The CSV names each test, and
the generator refuses a VERIFIED row with no evidence.

It does not mean:
- The case was run on a signed iPhone or Android build. No case has device
  evidence yet (PT-200).
- The backend it needs is deployed. The episode-correction cases (PT-027,
  PT-051, PT-052, PT-054, PT-056, PT-057, PT-060, PT-148) were verified
  against a scratch Postgres built from every migration, including
  `20261029100000_bleeding_episode_corrections.sql`. On 2026-10-29 that
  migration was also applied to staging and the same behavior checks passed
  there (rolled back, synthetic accounts). It is not on production, and no
  case has been run in the app against staging yet. PT-055 (deleting one
  day's entry) needs the follow-up migration
  `20261029120000_bleeding_observation_removal.sql`, verified on scratch
  Postgres only; it is not on staging or production yet. The same holds
  for PT-002 and `20261029130000_bleeding_episode_end_unknown.sql`.

CI passing is not a claim that all 200 cases are covered.
