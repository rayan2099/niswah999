# Privacy & Compliance Audit — Findings Register (Phases 2A/2B)

> **Status update (2026-09-05, latest wave):** This document is the frozen original audit (2026-09-04), preserved as-is for historical reference. `PC-001` (decorative consent) and `PC-002` (no account deletion) are **VERIFIED_CLOSED**. `PC-003`, `PC-004`/`RD-007`, `PC-006` are **PARTIALLY_REMEDIATED**. `PC-007`'s core finding (no retention duration defined) remains **OPEN**, but its addendum (local device data surviving account deletion) is now **VERIFIED_CLOSED** — local cycle/prayer/pregnancy data is cleared on account deletion, tested. | PC-001 | Consent (CONS) | **PC0** | Account creation / all sensitive data collection | The sign-in screen's "I agree to the Privacy Policy and Terms of Use" checkbox does not gate anything. Its state (`_agreed`) is read only by its own visual toggle; the Email/Phone/Google sign-up buttons' `onPressed` handlers never check it. Combined with RD-007 (the linked policy text isn't even tappable), the app currently collects health, pregnancy, religious, and location data from every user **with no functioning consent gate of any kind** — not broken-link-but-required, but genuinely optional and unenforced. | `lib/features/auth/presentation/screens/sign_in_screen.dart` — `_agreed` declared line 178, only used lines 311/318-339 (checkbox rendering); never referenced by `_AuthChoiceButton`/Google button `onTap`/`onPressed` | **PRODUCT/POLICY + LEGAL INTERPRETATION REQUIRED** (whether explicit consent is legally required, and what "informed" means, is a legal determination; the technical fact that it doesn't gate the flow is not in dispute) | YES | OPEN |

The database schema is correctly designed for cascade deletion (`ON DELETE CASCADE` from `auth.users` across 15+ tables), but there is no code path in `lib/` that ever calls it.
