### Positive controls confirmed (not findings — recorded as evidence for the launch-gate table)

- **AUTHN-01 PASS** — `dr-niswah-chat` performs real server-side JWT verification via `userClient.auth.getUser()`, not just header-presence checking. (`index.ts:206-231`)
- **AUTHZ-01 PASS** — RLS on `chat_messages` requires an `EXISTS` check that the target `thread_id` belongs to the caller on INSERT, closing an otherwise-plausible thread-hijack path. (`supabase/migrations/20260824115900_dr_niswah_chat_threads.sql:76-85`)
- **AUTHZ-02 PASS** — `flagged_conversations` has RLS enabled with zero client policies (default-deny), and is only ever written via the service-role client inside the Edge Function — correct use of the service role, confined to a single, justified insert path. (`index.ts:246-254`; migration file)
- **BR-001 PASS** — Red-flag detection runs and is logged independently of whether the Gemini call itself succeeds, so an urgent symptom is never silently dropped just because the AI call failed. (`index.ts:241-281`)
- **PAG (positive)** — `CommunityRepositoryImpl.getPosts` explicitly batches per-page comment/like counts via two `inFilter` queries instead of a per-post round trip — a correctly avoided N+1 pattern. (`community_repository_impl.dart:63-89`)
